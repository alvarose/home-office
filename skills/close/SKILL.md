# /home-office:close

Leave everything so that a fresh session can continue from files alone. Then the session ends.

Every git command you give the user (commit, merge, push, worktree removal, branch deletion) names its repo: `git -C <absolute repo path> …`, one command per code block. The session runs in the work folder, not in the repos, so a bare `git …` fails there.

Write STATE, DECISIONS, board and log in the project's `language` (see "Language" in `${CLAUDE_PLUGIN_ROOT}/core/WORKFLOW.md`), keeping the templates' sections and their order.

1. Identify the feature this session worked on (or the short-lane change). If a task is still open in any of its worktrees (`python3 "${CLAUDE_PLUGIN_ROOT}/scripts/ho.py" task-status --worktree <wt>` → `active: true`), close it with `task-end` and record the result (`task-end` runs the checks if no gate ran; for a TASK dropped before any work, add `--no-checks`).
1b. **Waits.** Run `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/ho.py" waiting list --state all --feature NN-name`. Act first on answered rows not yet acted on (then `waiting acted W-NNN`); every open row stays open and its id goes under "Blocked" in `STATE.md`.
2. **STATE.md**: rewrite it from the template. Six header lines (status, last session = today + role, branches, rework count, stream, project: keep the existing rework count, `Stream:` and `Project:` lines — `ho.py task-end` keeps the rework count) and four sections (done, next, blocked/open questions, decisions this session). About 20 lines. Be concrete in "Next": the exact TASK or step.
3. **DECISIONS.md** of the feature: add the decisions taken in this session. If it belongs to a batch, add rule-level decisions to the batch's `DECISIONS.md` too.
4. **Board**: update the feature's row (phase/gate, date, next step) under its project (`Project:` line) and stream; keep its "touches" rows in the other projects in step.
5. **Commits** → gate 4: TASKs that passed their gate are usually committed on the feature branch already (`new` § Execute step 5). For any passed TASK still uncommitted, follow that step (`commit: ask|auto`). For anything else with changes, show `git -C <path> diff --stat` and propose a commit message; the user commits. Never merge or push yourself, and never commit on the base branch. Every push and merge you ask the user to do is filed as a row of the waiting inbox (`ho.py waiting add --kind push|merge …`, `--action` with the `git -C <repo> …` command, `--blocks` what it unblocks), so it does not live only in this message; if one is already open for the same command, do not file it twice.
5b. **Sync once more, before proposing merges.** For each worktree of the feature, `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/ho.py" sync --worktree <wt> --base <repo base>` (after the commits of step 5 are in; a dirty worktree or an open TASK is refused). `merged` means the branch changed: say it, and that the checks must run again before the merge (`ho.py check`, cached when nothing changed). `conflict` (aborted, nothing changed, `files` listed) is told to the user with the files **before** the merge is proposed: the merge will conflict; file a wait (`ho.py waiting add --kind merge …`) or propose a TASK to resolve it. Never resolve it by hand.
6. **Feature finished?** The full checks of every touched repo (and the consumers of a changed shared package) already ran before gate 3 (`new` § "Review → gate 3", step 0); do not run them again unless files changed since: if you must, use `ho.py check`, whose cached pass answers at once. Propose merging `feature/NN-name` into each repo's base (its `base`, else `base_branch`) repo by repo, in `layers` order, and mention any shared package that must be published first (see "Shared packages" in the PLAN). The user merges. When the user confirms the merges, offer to remove the worktrees and branches with the helper, repo by repo, never with git by hand: `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/ho.py" worktree-remove --repo <repo> --dest <worktree> --branch feature/NN-name --base <repo base>` (add `--delete-branch` only with the user's permission). It refuses while a TASK is open, while there are uncommitted changes, and, with `--delete-branch`, if the branch is not merged into the base (it uses `git branch -d`, never `-D`). If it says only ignored files or submodules are left, retry with `--force`. Report each repo's result in one line. When the user confirms a push or merge, record it (`ho.py waiting answer W-NNN "done"`, then `acted`). Mark the feature "done" on the board. If `STATE.md` has a `Stream:` line, set the feature's roadmap row in the stream's `stream.md` to `done`, update the stream's Status, and offer the next planned one: "Next in the stream: <outcome>. Start it with `/home-office:stream next <stream>`." (If none is left, say the stream's roadmap is complete.) In the Claude desktop app, then archive its sessions: list those titled `feat: NN-name` (`mcp__ccd_session_mgmt__list_sessions`) and archive the idle ones other than this one with `mcp__ccd_session_mgmt__archive_session` (reason "NN-name done"). With `archive: ask` ask the user once first, in one line; with `auto` just do it. Archiving a session also archives its finished, idle side sessions, so skip any whose other children are still in use. If a call is refused, follow `project` § "Archiving sessions".
7. **Knowledge**: list what should be promoted to a knowledge source (new rules, architecture changes) so the user can add it. If any file listed in `generated_from` changed, warn that the generated files inside the repos must be regenerated.
8. **Short lane**: make sure its line is in the log, with its project.
9. End with one line of links to what you wrote (`STATE.md`, `DECISIONS.md`, the board; see `new` § "Links to documents"), then: "Session closed. Continue with `/home-office:resume NN-name` in a new session."
10. **Last, desktop app only, feature done**: offer to archive this session itself (`mcp__ccd_session_mgmt__archive_session` with `session_id: "self"`; same ask/auto rule). It ends the conversation, so it must be the very last action, after the final message's content. Skip it if the feature is not done.
